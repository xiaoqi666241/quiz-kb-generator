第03页｜1. 计算机系统的层次结构
──────────────────────────────────────────────────────────
标题：1. 计算机系统的层次结构

知识摘要：
计算机系统可以从硬件和软件协同工作的角度划分为多个层次。硬件提供计算、存储和输入输出能力；操作系统管理硬件资源并向上层提供服务；编译程序等系统软件帮助用户程序转换和运行；应用程序面向具体任务。各层通过约定的接口协作，上层利用下层提供的功能。

概念说明：
硬件是计算机系统运行的物理基础，包括处理器、存储器、输入设备、输出设备及连接它们的部件。仅有硬件并不能直接满足所有应用需求，还需要软件组织和管理硬件资源。操作系统负责进程管理、存储管理、文件管理和设备管理等工作，使应用程序能够以相对统一的方式使用计算机。编译程序则将高级语言程序转换为机器能够执行的形式。应用软件最终面向用户任务，例如文字处理、数据分析和图像编辑。

层次关系：
从用户角度看，通常通过应用程序完成任务；应用程序调用操作系统提供的服务；操作系统再通过驱动程序和硬件接口控制具体设备。层次划分并不意味着各层完全独立，而是强调职责分工和接口约定。下层发生变化时，只要接口保持兼容，上层程序就可能不需要进行大幅修改。

理解实例：
用户保存一份文档时，应用程序发出保存请求，操作系统负责文件和设备相关管理，存储设备最终完成数据保存。这个过程体现了应用软件、操作系统和硬件之间的协作。

易混淆点：
硬件与软件是组成角度的划分；层次结构是系统组织和功能依赖关系的描述。不要把某一个软件层次误认为物理硬件部件。

知识范围：
包含：系统层次、硬件与软件的分工、层次间接口和协作关系；不包含：操作系统内核实现、编译器优化算法及具体驱动程序代码。


第04页｜2. 计算机硬件的五大组成部分
──────────────────────────────────────────────────────────
标题：2. 计算机硬件的五大组成部分

知识摘要：
经典计算机硬件通常概括为运算器、控制器、存储器、输入设备和输出设备。运算器与控制器共同构成中央处理器的核心部分，五类部件相互配合完成信息处理任务。

组成与职责：
运算器主要完成算术运算和逻辑运算，例如加法、减法、比较以及逻辑判断。控制器负责解释指令并组织各部件按照规定步骤工作，它会根据指令要求发出控制信号。存储器用于保存程序和数据，为处理器提供执行所需的信息。输入设备将外部信息转换为计算机能够处理的形式，例如键盘输入字符、鼠标输入操作信息。输出设备则将处理结果呈现给用户，例如显示器显示文字和图像，打印机输出纸面材料。

部件协作：
以计算两个数并显示结果为例，输入设备接收数据，数据和相关程序被存入存储器；控制器组织取指和执行过程；运算器完成计算；结果可以暂存在寄存器或存储器中，最后由输出设备呈现。这个例子说明，计算机完成任务并非依靠某一个部件单独工作，而是依靠各部件协调配合。

重要区分：
存储器负责保存信息，不等同于运算器；控制器负责协调和控制，不直接承担所有算术运算；输入设备负责信息输入，输出设备负责结果输出。CPU 通常指中央处理器，不能把它与整台计算机混为一谈。

知识范围：
包含：五大组成部分的名称、基本职责及协作关系；不包含：现代 CPU 内部微架构、专用加速器结构和具体芯片电路设计。


第05页｜3. 冯·诺依曼结构与存储程序思想
──────────────────────────────────────────────────────────
标题：3. 冯·诺依曼结构与存储程序思想

知识摘要：
存储程序思想强调将程序指令和数据以编码形式存放在存储器中，计算机在控制器协调下按照指令规定的步骤自动执行程序。这一思想是理解经典计算机工作方式的重要基础。

基本含义：
程序由一条条指令组成，指令描述计算机应执行的操作以及操作所需的信息。数据是指令处理的对象。采用存储程序方式时，指令和数据都可以存放在存储器中，处理器根据程序计数器等控制信息确定后续要读取的指令位置，再对指令进行解释和执行。程序执行过程中，控制流程可以按顺序推进，也可以根据条件或转移指令改变后续执行位置。

工作过程示意：
首先，程序和数据进入存储器；随后，处理器从指定位置读取指令；控制部件分析指令所表达的操作；执行部件完成相应操作；必要时读取数据或将结果写回存储器。上述过程持续进行，直到程序结束或执行流程转向其他位置。

理解意义：
存储程序思想使计算机能够通过更换存储器中的程序完成不同任务，而不必为每一种任务重新设计整套硬件。硬件提供通用执行能力，程序则描述具体任务步骤。它体现了计算机通用性的重要来源。

易混淆点：
指令和数据虽然都以编码形式存放，但二者含义不同：指令规定要做什么，数据是被处理的信息。不能因为它们都存储在存储器中，就认为二者在功能上相同。

知识范围：
包含：存储程序思想、指令与数据的存储、按指令执行程序的基本过程；不包含：不同体系结构的深入比较及计算机发展史细节。


第06页｜4. 中央处理器 CPU 的基本功能
──────────────────────────────────────────────────────────
标题：4. 中央处理器 CPU 的基本功能

知识摘要：
中央处理器是计算机的核心处理部件，主要负责取出指令、分析指令、执行指令，并协调计算机各部件工作。其基本组成可从运算部件和控制部件两个方面理解。

运算功能：
运算部件按照指令要求对数据进行处理，包括算术运算和逻辑运算。算术运算涉及数值计算，逻辑运算涉及比较、判断以及逻辑关系处理。运算所需的数据可能来自寄存器，也可能需要通过存储系统读取。运算结果通常暂存在处理器内部或按指令要求写入指定位置。

控制功能：
控制部件负责组织指令执行。它需要确定当前指令的位置，读取指令内容，分析操作类型和操作对象，并向相关部件发出控制信号。控制部件还要协调数据传送、运算以及必要的存储器访问，使各个步骤按规定顺序完成。

基本工作链：
CPU 的工作可以概括为取指、译码和执行。取指是从存储器取得指令；译码是识别指令的操作要求；执行是完成指令规定的动作。不同指令的执行内容并不相同，有的进行运算，有的进行数据传送，有的改变程序执行顺序。

理解实例：
执行一条简单的加法指令时，处理器需要取得该指令，识别其为加法操作，准备操作数，完成相加，并保存结果。这个例子体现了控制与运算的配合。

易混淆点：
CPU 不等于主存，也不等于整台计算机。CPU 负责执行和控制，存储器负责保存信息，二者通过数据、地址和控制等信号进行协作。

知识范围：
包含：CPU 的基本职责、运算部件与控制部件的分工、指令执行概念；不包含：流水线、乱序执行、分支预测和多核缓存一致性等高级微架构细节。


第07页｜5. 指令周期与取指执行过程
──────────────────────────────────────────────────────────
标题：5. 指令周期与取指执行过程

知识摘要：
指令周期是处理器完成一条指令所经历的基本过程。通常可以从取指、译码和执行等环节理解；根据指令类型，还可能涉及访存和结果写回。

取指阶段：
处理器根据当前指令地址，从存储器中读取指令，并将其送入处理器内部供后续分析。指令地址通常由程序执行控制信息提供。取指完成后，处理器需要为后续指令做好地址准备；若当前指令会改变程序流程，则后续地址可能按指令要求调整。

译码阶段：
控制部件分析指令编码，识别需要执行的操作、操作数来源以及结果去向等信息。不同类型的指令具有不同的操作要求，因此译码结果会影响后续执行步骤。

执行阶段：
处理器根据译码结果完成相应操作。算术逻辑类指令可能调用运算部件；数据传送类指令可能涉及寄存器或存储器；转移类指令可能改变下一条指令的执行位置。若指令需要访问存储器，还要完成相应的读写操作。

过程示例：
假设程序需要将两个数相加并保存结果，处理器先读取加法指令，识别操作类型和操作数位置，再取得操作数并完成运算，最后把结果保存到指定位置。接下来处理器继续执行后续指令。

理解要点：
指令周期是对指令执行过程的概括，不代表所有指令都必须经历完全相同的内部步骤。简单指令和复杂指令的具体执行过程可能不同。

知识范围：
包含：取指、译码、执行以及可能出现的访存和写回环节；不包含：具体指令集时序图、流水线冲突和处理器周期级性能分析。


第08页｜6. 寄存器的作用
──────────────────────────────────────────────────────────
标题：6. 寄存器的作用

知识摘要：
寄存器是处理器内部容量较小、访问速度较快的存储部件，用于暂存指令执行所需的信息，例如操作数、地址、中间结果和控制状态等。

为什么需要寄存器：
处理器执行指令时，需要频繁使用少量数据和地址信息。如果每次操作都直接访问较慢的主存，会增加数据获取所需时间。寄存器位于处理器内部，能够为当前运算和控制过程提供临时存放位置，减少反复访问主存的需要。

常见用途：
一类寄存器用于保存参与运算的数据或运算结果；一类寄存器用于保存指令或指令地址；还有一些寄存器用于记录状态或辅助控制流程。不同处理器的寄存器名称、数量和具体用途可能不同，但共同特点是为处理器当前工作提供快速存储支持。

工作示例：
执行连续的算术操作时，处理器可以先将操作数放入寄存器，再由运算部件读取这些值完成计算。中间结果可以继续保存在寄存器中，供后续指令使用。若结果需要长期保存或供其他程序使用，则还需要按照程序要求写入存储器。

与其他存储部件的区别：
寄存器容量通常很小，直接服务于处理器当前执行过程；主存容量较大，用于存放正在运行的程序和数据；辅助存储器用于较长期保存信息。三者的用途和访问方式不同，不能互相替代。

知识范围：
包含：寄存器的特点、基本用途及其与主存的区别；不包含：具体指令集全部寄存器名称、位宽和专用寄存器编码。


第09页｜7. 存储器层次结构
──────────────────────────────────────────────────────────
标题：7. 存储器层次结构

知识摘要：
计算机通常采用由寄存器、缓存、主存和辅助存储器构成的多层次存储体系。不同层次在速度、容量和单位容量成本方面存在差异，通过分工协作满足处理器对速度和容量的不同需求。

层次特点：
寄存器位于处理器内部，容量小、访问速度快，主要服务于当前指令执行。高速缓存位于处理器与主存之间，用于保存近期或可能再次访问的数据副本。主存能够容纳正在运行的程序和数据，容量通常大于缓存，但访问速度相对较慢。辅助存储器用于较长期保存程序和文件，通常具有较大的存储容量，但访问速度一般低于主存。

层次结构的意义：
如果所有数据都采用速度很快但成本较高、容量较小的存储部件，系统成本会明显增加；如果全部采用容量大但速度较慢的存储部件，处理器又可能经常等待数据。通过多层次组织，可以让经常使用的信息尽量靠近处理器，同时保留较大容量的存储空间。

数据使用过程：
程序运行时，数据可能从辅助存储器进入主存，再根据处理器访问情况进入缓存或寄存器。处理器优先使用距离自身较近、访问更快的存储部件。不同层次之间的数据调入和管理由硬件及系统机制共同完成。

易混淆点：
“容量大”不代表“速度快”；“离 CPU 近”通常意味着访问更快，但容量和成本也有相应特点。存储层次是多个部件协作的体系，不是单一设备。

知识范围：
包含：寄存器、缓存、主存和辅助存储器的相对特点及层次意义；不包含：具体缓存替换算法、磁盘控制器实现和存储介质电路细节。


第10页｜8. 高速缓存 Cache 的作用
──────────────────────────────────────────────────────────
标题：8. 高速缓存 Cache 的作用

知识摘要：
高速缓存用于保存主存中近期访问或可能很快再次访问的数据副本，以减少处理器访问主存的平均等待时间。其有效性与程序访问的局部性特点有关。

时间局部性：
如果某个数据或指令刚刚被访问，那么在不久之后再次访问它的可能性较高。例如，循环程序可能多次使用同一个计数变量。缓存保存近期访问的信息，有机会在后续访问时直接提供数据。

空间局部性：
如果程序访问了某个存储位置，那么其附近位置在随后一段时间内也可能被访问。例如，程序按顺序处理数组元素时，访问一个元素后往往还会访问相邻元素。缓存通常以数据块为单位进行管理，因此能够利用相邻位置可能被访问的特点。

基本工作方式：
处理器需要读取数据时，先检查缓存中是否有对应内容。如果存在且有效，可以直接从缓存取得数据，这种情况称为缓存命中；如果缓存中没有所需内容，则需要从主存取得数据，这种情况称为缓存未命中。未命中时，相关数据可能被调入缓存，以便后续访问。

作用与限制：
缓存能够改善平均访问效率，但不能保证每次访问都命中。程序访问模式、缓存容量以及缓存管理策略都会影响实际效果。缓存也不是主存的永久替代品，它保存的是主存数据的副本。

知识范围：
包含：Cache 的目的、时间局部性、空间局部性、命中与未命中的基本含义；不包含：多核缓存一致性协议、具体映射方式和替换策略的实现细节。


第11页｜9. 总线及其分类
──────────────────────────────────────────────────────────
标题：9. 总线及其分类

知识摘要：
总线是计算机多个部件之间传送信息的公共通路。按传送信息的类型，常见的基本分类包括数据总线、地址总线和控制总线。

数据总线：
数据总线用于在部件之间传送数据或指令相关信息。处理器读取存储器内容时，需要通过相应通路取得数据；写入数据时，也需要将待保存的信息传送到目标部件。数据总线所承载的信息与具体读写操作有关。

地址总线：
地址总线用于指明本次访问所涉及的存储位置或输入输出设备位置。处理器需要读取某个存储单元时，必须先提供相应地址，使目标部件能够确定访问位置。地址信息回答的是“访问哪里”，而不是“传送什么数据”。

控制总线：
控制总线用于传送控制和状态相关信号，例如读写控制、请求和响应等信息。控制信号帮助各部件明确当前操作类型及协作时机。

综合示例：
处理器从某个存储位置读取数据时，需要给出目标地址，发出相应读控制信号，并通过数据通路接收返回的数据。这个过程体现了地址信息、控制信息和数据信息的不同作用。

易混淆点：
地址总线传送的是访问位置相关信息，数据总线传送的是实际数据，控制总线传送的是控制或状态信息。三者在功能上不同，但在一次完整的数据交换中通常需要配合工作。

知识范围：
包含：总线概念及数据、地址、控制总线的基本作用；不包含：PCIe 等具体总线协议的电气规范、编码规则和时序细节。


第12页｜10. 输入输出系统与中断
──────────────────────────────────────────────────────────
标题：10. 输入输出系统与中断

知识摘要：
输入输出系统负责计算机与外部设备之间的信息交换。中断机制允许设备或其他事件向处理器提出服务请求，使处理器能够在适当时机转去处理相关事件。

输入输出系统的职责：
计算机需要通过外部设备获取信息并向外部输出结果。键盘、鼠标和传感器等设备可提供输入；显示器、打印机和扬声器等设备可呈现输出。由于外部设备的工作方式、速度和数据格式各不相同，计算机需要相应的接口和控制机制完成协调。

中断的基本含义：
当设备或程序运行过程中出现需要处理的事件时，可以通过中断机制通知处理器。处理器在满足响应条件时暂停当前程序的正常执行流程，转去执行相应的处理程序；处理完成后，再根据系统规定返回原来的执行流程或继续后续工作。

中断的价值：
如果处理器始终采用反复查询设备状态的方式等待输入输出事件，可能会浪费处理时间。中断机制让设备在需要处理器关注时发出请求，有助于提高处理器与外部设备协作的灵活性。

过程示例：
用户按下键盘按键后，键盘相关接口产生事件通知。处理器响应请求，获取按键相关信息并交由系统处理，随后应用程序便可以接收到相应输入。这个过程说明外部设备能够通过中断机制与处理器协作。

易混淆点：
输入输出是主机与外部设备之间的信息交换；中断是处理器响应事件的一种控制机制。中断并不是输入输出设备本身，也不意味着所有输入输出操作都只能通过中断完成。

知识范围：
包含：输入输出系统的职责、中断的基本概念和作用；不包含：DMA 控制器细节、中断向量表实现及操作系统中断处理代码。


第13页｜综合复习与知识点联系
──────────────────────────────────────────────────────────
一、从系统整体理解
计算机组成原理中的各知识点并非彼此孤立。系统层次说明软件如何使用硬件；硬件五大组成部分说明计算机有哪些基本功能部件；存储程序思想说明程序和数据如何进入存储器并由处理器执行；CPU 与指令周期说明处理器如何组织具体操作。

二、从信息流理解
程序和数据存放在存储系统中，处理器通过地址信息确定访问位置，通过控制信号组织读写，通过数据通路取得指令和数据。寄存器为当前运算提供快速暂存空间，Cache 利用局部性减少部分主存访问等待，主存与辅助存储器则分别承担运行期间存储和长期保存等任务。

三、从设备协作理解
输入设备提供外部信息，输出设备呈现处理结果，总线为各部件之间的信息传送提供通路。中断机制让处理器能够响应设备或程序运行中的特定事件。由此可见，计算机完成一个任务通常需要处理器、存储器、总线和输入输出系统共同参与。

四、复习时应掌握的区分
1. 运算器负责运算，控制器负责组织和控制。
2. 指令说明操作，数据是操作对象。
3. 寄存器、缓存、主存和辅助存储器在容量、速度及用途上不同。
4. 时间局部性强调近期访问可能再次发生，空间局部性强调邻近位置可能被访问。
5. 地址总线表示访问位置，数据总线传送数据，控制总线传送控制或状态信息。

五、复习方法
先用自己的语言解释概念，再结合一个小例子描述工作过程，最后尝试比较相近概念。遇到无法从本资料中找到依据的问题，应先查阅课程教材，不应仅凭猜测作答。

## 二、分阶段会议议程

### 2.1 启动会（10.27 第 1 天）

**目标**：统一产品形态、接口契约、分工与当日交付物。

**议程**：
1. 确认产品形态：微信原生小程序（PC 端与手机端可用），删除 Web/web-view。
2. 确认演示方式：PC 微信开发者工具现场演示；本地 FastAPI + 勾选“不校验合法域名”。
3. 确认接口契约 v1.1：`/generate`、`/extract`、字段、超时、兜底。
4. 确认知识块 JSON 模板：`id/name/summary/source_excerpt/scope`。
5. 确认三人当日任务与验收标准。
6. 确认 Token 提醒与 API Key 管理方式。

**当日交付物检查**：
- [ ] `/generate` 接口契约 v1.1 已同步给何、刘
- [ ] FastAPI 能启动，`/docs` 可访问
- [ ] 硬编码假题目覆盖单选+填空，字段齐全
- [ ] 何拿到假数据，小程序内假数据闭环跑通
- [ ] 刘确认 2 份演示资料并开始资料 1 知识块
- [ ] 百炼控制台 Token 提醒已设置
- [ ] `.env.example`、`.gitignore` 已建

### 2.2 每日站会（10.28—11.5，每天 10～15 分钟）

**目标**：同步进度、暴露卡点、调整当日优先级。

**议程**：
1. 每人回答三问：昨天完成了什么？今天要做什么？有什么卡点？
2. 封确认接口契约是否有变更，如有变更当场通知。
3. 刘确认测试发现的问题是否已提给对应负责人。
4. 确认当日里程碑是否可达；不可达则当场调整。

**每日检查清单**：
- [ ] 昨日待办是否全部完成或已说明原因
- [ ] 今日每人是否有明确可交付物
- [ ] 是否有阻塞项需要封协调
- [ ] 接口契约是否有变更并已通知
- [ ] Token 消耗是否在预算内
- [ ] 测试发现的问题是否已记录并分配

### 2.3 联调会（10.31 第 5 天）

**目标**：全链路首次完整走通，确定演示脚本和兜底策略。

**议程**：
1. 何演示：选预置资料→生成/加载题目→逐题作答→对错与解析→结果页。
2. 封演示：后端 `/generate` 真实调用、LLM 失败兜底切换、`/extract` 小样本。
3. 刘演示：按答辩脚本走一遍，记录断点和体验问题。
4. 讨论并确定：演示用哪份资料、预期生成多少知识块/题目、备用方案。
5. 确认双层兜底触发条件和提示文案。

**联调检查清单**：
- [ ] 小程序能请求本地 FastAPI 并拿到题目
- [ ] 答对显示“正确”，答错显示“错误”
- [ ] 答错后展示正确答案+解析，解析引用原文
- [ ] LLM 超时/JSON 失败时返回后端预置题库并提示切换
- [ ] 关闭 FastAPI 后前端切内置预置题库并提示
- [ ] `/extract` 小样本能返回知识块
- [ ] 刷新/重进后题库和答题记录不丢
- [ ] PC 宽屏和手机尺寸下无样式错乱
- [ ] 演示脚本计时在 8 分钟内

### 2.4 排练会（11.3 第 8 天、11.4 第 9 天、11.5 第 10 天）

**目标**：PPT 定稿、答辩流程计时、问答准备。

**议程**：
1. 刘按 PPT 逐页讲一遍，封/何按分工补充技术页和操作。
2. 计时：项目介绍控制在 8 分钟，问答 2 分钟。
3. 封准备技术问答清单，刘准备项目思路问答清单。
4. 模拟评委提问 3～5 个，现场回答。
5. 确认答辩设备、网络、API 余额、预置数据已就绪。

**排练检查清单**：
- [ ] PPT 12 页定稿，无错字、无矛盾数据
- [ ] 主讲人刘，技术页封，操作何，分工明确
- [ ] 项目介绍计时 ≤8 分钟
- [ ] 问答环节能覆盖：为什么预置知识块、AI 出题质量、Token 成本、为什么不做多端同步、PC/手机可用性
- [ ] 演示流程在开发者工具上操作 3 遍无报错
- [ ] 兜底切换演示一遍成功
- [ ] 手机真机截图已留存（首页、选资料、答一题、看解析）
- [ ] 答辩电脑已启动 FastAPI，`/docs` 可访问
- [ ] API Key 余额充足
- [ ] 预置题库已加载

### 2.5 提交前确认会（11.4 第 9 天）

**目标**：确认提交包内容完整、命名正确、已发出。

**议程**：
1. 刘展示提交包内容：PPT、项目说明 Markdown、项目计划 docx。
2. 逐项核对命名、格式、页数、错字。
3. 确认压缩包命名：`乘微逐光队+刷题软件知识块生成器.zip`。
4. 确认发送邮箱：`15762161816@163.com`。
5. 确认发送时间不晚于 11 月 5 日。

**提交前检查清单**：
- [ ] PPT 12 页，8+2 结构，无宣传性虚假数字
- [ ] 项目说明 Markdown 含附录，Mermaid 图可渲染
- [ ] 项目计划 docx 排版正常，目录、页码、表格无错位
- [ ] 三份材料中模型名统一为“阿里云百炼 DeepSeek 系列模型”
- [ ] 三份材料中 PPT 主讲人统一为刘，技术页封，操作何
- [ ] 压缩包命名正确
- [ ] 邮件正文写清团队名称、项目名称、联系人
- [ ] 发送后截图留存

- [ ] 现场网络不稳：本地服务+双层预置题库+提前到场检查（不做视频备份）
